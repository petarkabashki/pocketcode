# Implementation Plan: Agent Default Profiles

**Branch**: `001-agent-default-profiles` | **Date**: 2026-03-06 | **Spec**: [spec.md](spec.md)
**Input**: Feature specification from `specs/001-agent-default-profiles/spec.md`

## Summary

Every agent gets a **default agent profile** — a named bundle of LLM selection, tool allowlist, extra system-prompt files, and tool-confirmation policies. Profiles are declared inline in `plugin.yaml` (optional `default_agent_profile` block) or synthesised automatically from the agent's existing top-level fields. Workspace-local profiles live in `.pocketcode/agent-profiles/*.yaml`. A new `AgentProfileManager` component loads and indexes all profiles. The CLI gains `/agent-profile list|show|switch|clone` commands and a `--agent-profile` flag on `/agent`. Agent activation always sets an `ActiveAgentProfile` on the engine. `AgentRuntime` uses the active profile to override LLM selection, filter tools, and append extra prompts; `ToolRuntime` uses it for two new confirmation-policy tiers.

## Implementation Steps

### Step 1 — `AgentProfile` dataclass (`runtime_models.py`)

Add `AgentProfile` dataclass above the existing `AgentDefinition`. Fields: `name`, `agent`, `description`, `llm_profile`, `extra_prompts`, `tools` (`List[str] | None`), `tool_confirmation` (`Dict[str, Any]`), `source` (`"synthesised"|"plugin"|"workspace"`), `source_path` (`Path | None`).

Add one new field to `AgentDefinition`: `default_agent_profile: AgentProfile | None = None`.

No changes to any other `AgentDefinition` fields.

### Step 2 — `AgentProfileManager` (`agent_profile_manager.py`)

New module. `AgentProfileManager.__init__(workspace_root: Path)` stores `_workspace_profiles_dir = workspace_root / ".pocketcode" / "agent-profiles"`.

`load(agent_definitions: Dict[str, AgentDefinition])`:
1. Clear `_profiles`.
2. For each `AgentDefinition` with `default_agent_profile` set: register it under its `name`.
3. For each `AgentDefinition` without `default_agent_profile`: synthesise an `AgentProfile` (source=`"synthesised"`, name=qualified agent name, pull `llm_profile`, `tools`, `tool_confirmation={}`, `extra_prompts=[]` from definition), register it.
4. Scan `_workspace_profiles_dir` (if it exists) for `*.yaml`. Parse each: construct `AgentProfile(source="workspace", source_path=file_path)`. On name collision: log `WARNING` naming both sources; let workspace file win.

`get(name)`, `list()`, `clone(src, new)`, `save(profile)` as described in data-model.md.

`clone` flow: fetch source → copy fields, assign `new_name`, set `source="workspace"`, set `source_path = _workspace_profiles_dir / f"{new_name}.yaml"` → guard against existing file → call `save()` → re-run `load()` with current agent definitions.

### Step 3 — Plugin manager reads `default_agent_profile` (`plugin_manager.py`)

In `_register_agent_definition`, after reading all existing keys, check for `raw_agent_dict.get("default_agent_profile")`. If present and a `dict`: construct an `AgentProfile` from it (source=`"plugin"`, `agent=qualified_name`, `name=block.get("name") or qualified_name`, remaining fields from block). Assign to `definition.default_agent_profile`. Log a `DEBUG` message. If absent: leave `definition.default_agent_profile = None` (synthesised later by `AgentProfileManager.load()`).

### Step 4 — Engine wires up `AgentProfileManager` (`engine.py`)

After `self._plugins = PluginManager(...)` and `.load()`:

```python
self._agent_profile_manager = AgentProfileManager(self._workspace_root)
self._agent_profile_manager.load(dict(self._plugins.agents))
self.active_agent_profile: AgentProfile | None = None
```

Add `set_active_agent_profile(name: str | None)` method:
- If `name` is None: set `active_agent_profile = None`.
- Else: `profile = self._agent_profile_manager.get(name)` → raise `ValueError` if not found → set `active_agent_profile = profile`.

Modify `set_agent(name)` (the method called by `/agent`): after setting `self.current_agent = name`, look up the agent's default profile name and call `self.set_active_agent_profile(default_name)`.

Add `active_agent_profile` to `status()` return dict: `"active_agent_profile": self.active_agent_profile.name if self.active_agent_profile else None`.

In `reload()`: call `self._agent_profile_manager.reload(dict(self._plugins.agents))`. Re-activate the current agent's default profile (or re-fetch the named profile if a non-default was active).

Pass `active_agent_profile` into `shared_store` at the start of each `process_request` call so `AgentRuntime` and `ToolRuntime` can read it.

### Step 5 — `AgentRuntime` applies profile overrides (`agent_runtime.py`)

**LLM resolution** (`_resolve_llm_profile`): between tier 4 (dynamic override) and tier 5 (agent definition llm_profile), insert:

```python
# Tier 4.5: active agent profile llm_profile
profile = shared_store.get("active_agent_profile")
if profile and profile.agent == agent_name and profile.llm_profile:
    return profile.llm_profile
```

**Tool filtering** (`_run_pocketflow_agent`, after `resolve_tools_for_agent()`): if `profile.tools is not None`, intersect resolved tool list with `profile.tools`. Tools not in the allowlist are removed from the description sent to the LLM and their execution is denied at `ToolRuntime` level.

**Extra prompts** (in system prompt assembly): if `profile.extra_prompts` is non-empty, resolve each path (first relative to `profile.source_path.parent` if set, then relative to `workspace_root / ".pocketcode"`). Read file contents. Append to `shared["_agent_system_prompt"]` after the base system prompt. Log `WARNING` and skip if a file is not found.

### Step 6 — `ToolRuntime` adds profile confirmation tiers (`tool_runtime.py`)

In `_resolve_confirmation_policy`, current tiers 1–8. Insert two new checks:

After tier 1 (`session[agent][tool]`), insert **tier 1.5**:
```python
profile = shared_store.get("active_agent_profile")
if profile and profile.tool_confirmation.get("overrides", {}).get(tool_name):
    return profile.tool_confirmation["overrides"][tool_name]
```

After tier 4 (`session[agent].default`), insert **tier 4.5**:
```python
if profile and profile.tool_confirmation.get("default"):
    return profile.tool_confirmation["default"]
```

Update the docstring to document the new 10-tier order.

### Step 7 — CLI `/agent-profile` commands (`command_handler.py`)

Add to the normalised aliases: `"agent-profile"` → `"agent-profile"` (no alias needed).

Add `elif first_token == "agent-profile":` dispatch → `_handle_agent_profile_command(parts, engine, cli_context)`.

Implement `_handle_agent_profile_command`:

| Sub-command | Action |
|-------------|--------|
| `list` | Print each profile: name, agent, llm, source |
| `show <name>` | Print all fields if profile found; error if not |
| `switch <name>` | `engine.set_active_agent_profile(name)`. If `profile.agent != engine.current_agent`: print warning, also call `engine.set_agent(profile.agent)` |
| `clone <src> <new>` | `engine._agent_profile_manager.clone(src, new)`, print path |

Modify the existing `/agent` handler: before calling `engine.set_agent()`, check `parts` for `--agent-profile <name>`. If found, record `profile_name` and call `engine.set_active_agent_profile(profile_name)` after the agent switch (overriding the default that `set_agent` sets).

### Step 8 — Tab completers (`completers.py`)

Add `AgentProfileCompleter(Completer)`: completes agent profile names from `engine._agent_profile_manager.list()` for `/agent-profile show`, `/agent-profile switch`, `/agent-profile clone` (first arg position). Wire into `PocketCodeTextualApp`'s input completer list.

### Step 9 — Status bar (`textual_app.py`)

In `_update_status()`, read `status["active_agent_profile"]`. Insert a `| Profile: {profile_name}` segment into the status bar format string between the Agent segment and the LLM segment:

```
Runtime flow: {flow} | Agent: {agent} | Profile: {profile} | LLM: {llm} ({model})
```

Fallback: `profile = status.get("active_agent_profile") or "-"`.

### Step 10 — Unit tests

**`tests/unit/test_agent_profile_manager.py`**:
- `TestAgentProfileSynthesis`: manager synthesises a profile for an agent with no `default_agent_profile` block; name equals qualified agent name.
- `TestAgentProfilePluginDeclared`: manager uses explicit name from plugin-declared `default_agent_profile`.
- `TestWorkspaceProfileLoading`: valid YAML file in `tmp_path/agent-profiles/` is loaded and indexed.
- `TestWorkspaceProfileCollisionWarning`: workspace file with same name as synthesised default emits `WARNING` and workspace wins.
- `TestAgentProfileClone`: `clone(src, new)` creates file, updates registry, raises `ValueError` if `new` already exists.
- `TestInvalidProfileYaml`: malformed YAML is skipped with `WARNING`; remaining profiles still load.

**`tests/unit/test_agent_profile_resolution.py`**:
- `TestLlmProfileTierOrder`: active_agent_profile.llm_profile wins over agent_definition.llm_profile; CLI override wins over both.
- `TestToolFilteringWithProfile`: tool list is intersected with profile.tools when profile.tools is not None.
- `TestToolFilteringInheritAll`: when profile.tools is None, full tool set is returned.
- `TestConfirmationTierProfileOverride`: profile override wins over config-agent-default but loses to session-agent-tool.
- `TestConfirmationTierProfileDefault`: profile default wins over config-agent-default.
- `TestExtraPromptsResolution`: paths resolved relative to profile file dir → .pocketcode/ fallback → warning if missing.
