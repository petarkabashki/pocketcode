# Contract: Session History CLI Surface

## Purpose

Define the shared slash-command surface for workspace-scoped saved session history so basic CLI, one-shot mode, and Textual UI all target the same engine behavior.

## Command Family

All session history actions are rooted at:

```text
/session <subcommand> [args]
```

## Subcommands

### `/session show`

- Purpose: Display the current active session identity and summary.
- Output requirements:
  - active session id
  - title
  - last updated timestamp
  - whether the session is newly created or resumed

### `/session list`

- Purpose: List saved sessions for the current workspace.
- Output requirements:
  - one row per saved session
  - title
  - last updated timestamp
  - active-session marker
  - unreadable-session marker when applicable
- Empty-state requirement:
  - when no prior sessions exist, print a clear no-saved-sessions message instead of an empty table

### `/session new`

- Purpose: Start a fresh session without deleting or overwriting previous sessions.
- Behavior requirements:
  - create a new saved session record with an autogenerated title
  - switch the engine to that session immediately
  - preserve all previously saved sessions
  - print the new session identifier and title

### `/session resume <session_id>`

- Purpose: Continue a prior saved session.
- Behavior requirements:
  - load the requested session only if it belongs to the current workspace and is readable
  - restore the selected session as active
  - reject unknown or unreadable session ids with an explicit error
  - print confirmation that the session was resumed

### `/session delete <session_id>`

- Purpose: Remove one saved previous session.
- Behavior requirements:
  - require explicit confirmation before deletion
  - reject deletion when `session_id` is the active session
  - remove only the targeted session
  - print a success or refusal message

### `/session clear-all`

- Purpose: Remove all saved previous sessions in the workspace.
- Behavior requirements:
  - require explicit confirmation before deletion
  - preserve the active session
  - report when there are no prior sessions to clear
  - print how many sessions were removed

## Error Handling

- Unknown subcommands must print usage help for `/session`.
- Unknown or unreadable session ids must fail explicitly and must not switch to a different session.
- Attempts to delete the active session must be blocked with a clear message.
- Workspace mismatch must prevent session visibility and resume.

## Textual Alignment

- Any Textual session picker or control-center action must call the same engine methods that back these commands.
- Textual UI may present richer affordances, but it must not expose behavior that contradicts this CLI surface.
