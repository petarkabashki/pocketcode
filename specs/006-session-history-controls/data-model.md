# Data Model: Session History Controls

## Entity: Saved Session

- Purpose: Represents one workspace-scoped conversation session that can be started, resumed, listed, or deleted.
- Fields:
  - session_id: stable unique identifier used by CLI and Textual UI actions
  - title: autogenerated display title shown in history lists
  - created_at: creation timestamp in UTC
  - updated_at: last-modified timestamp in UTC
  - workspace_root: resolved workspace path the session belongs to
  - active_agent: last active flow/agent name for resume
  - active_profile: active agent profile name, if any
  - active_mode: active mode name, if any
  - enabled_skills: ordered list of enabled skill names
  - global_llm_profile: persisted global LLM override, if any
  - session_confirmation_overrides: session-scoped tool confirmation state restored only when that session is resumed
  - transcript: ordered list of transcript entries
- Validation Rules:
  - `session_id` must be unique within `.pocketcode/state/sessions/`.
  - `title` must be system-generated and non-empty.
  - `workspace_root` must match the current workspace before a session is listed or resumed.
  - The active session may be updated and resumed, but it must not be deletable.

## Entity: Session Transcript Entry

- Purpose: Stores one chronological piece of session history.
- Fields:
  - entry_id: stable entry identifier or monotonically increasing sequence number
  - timestamp: UTC timestamp for ordering and display
  - role: one of `user`, `assistant`, or `system`
  - content: textual content captured for the session history
  - run_id: identifier tying grouped transcript entries to a request execution, when available
  - metadata: optional structured details such as active agent or outcome summary
- Validation Rules:
  - Entries must preserve append-only chronological order within a session.
  - `role` must be constrained to supported runtime speakers.
  - `content` must be non-empty for user and assistant entries.

## Entity: Approval Decision

- Purpose: Captures the user’s answer to a tool approval prompt.
- Fields:
  - tool_name: the specific tool being approved or denied
  - agent_name: originating agent/flow name, if known
  - scope: one of `once`, `session`, `always`, or `deny`
  - decided_at: UTC timestamp of the interaction
  - arguments_preview: serialized argument summary shown in the prompt
- Validation Rules:
  - Approval scope applies only to `tool_name` and must not grant access to other tools.
  - `once` decisions must not persist beyond the current invocation.
  - `session` decisions must be stored only in the active session state and must not cross session boundaries.
  - `always` decisions must update persistent confirmation config independently of session history.

## Entity: Session History View Item

- Purpose: Represents the lightweight row shown in session history listings and pickers.
- Fields:
  - session_id: identifier used for resume or delete actions
  - title: autogenerated session label
  - updated_at: last updated timestamp shown to the user
  - is_active: whether the row corresponds to the currently active session
  - is_resumable: whether the backing session file is readable and valid
- Validation Rules:
  - Active sessions must be clearly marked and cannot be presented as deletable.
  - Unreadable sessions must be identified as unavailable rather than silently resumed.

## Entity: Active Session State

- Purpose: Holds the in-memory session currently attached to the engine.
- Fields:
  - session_id: active saved-session identifier
  - loaded_from_history: whether the session was resumed or newly created
  - dirty: whether in-memory session state differs from disk
  - last_run_summary: latest execution summary associated with the session
- Validation Rules:
  - Exactly zero or one active session may be attached to an engine instance.
  - Changing to a different session must replace session-scoped confirmation overrides with the selected session’s stored state.
  - Clearing history must never delete the active session.

## Relationships

- A Saved Session owns many Session Transcript Entries.
- A Saved Session may restore one Active Session State when resumed.
- Approval Decisions may be recorded as system metadata within a Saved Session and may also update runtime config depending on scope.
- Session History View Items are projections derived from Saved Session metadata for CLI and Textual presentation.
